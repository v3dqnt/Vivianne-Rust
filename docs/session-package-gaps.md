# The original `session` package group, and where Vivianne stands

The original `packages/session` is 22 packages (about 52 000 lines with tests) around one idea: a conversation is an
append-only event log in a versioned format, stored by a persistence backend, with derived views (projections), titles,
telemetry and a working directory. Vivianne keeps a conversation as an append-only log per thread (`runtime::store`, `runtime::log`) and derives
views from its messages (`runtime::session`, `runtime::session_stats`, `runtime::projection`). This file maps each original package to what
Vivianne has, says what was ported now, and says what is a deliberate difference or still open.

| Original | Vivianne | State |
|---|---|---|
| `session-format`, `session-format-catalog` (a file says which format it is; adjacent migrations; a gap-free chain checked up front; unsupported and malformed told apart; source kept) | `runtime::formats` (`classify`, `restore`, `check_chain`, `stamp`) | **Ported.** A thread says which format it is. A file with no version is format 0 and is carried forward; a newer one is refused and never written over; a damaged one is reported by name. The original's migrations (v0 to v4) turn its event-log format into later ones; Vivianne has two steps: 0 to 1 (a version field) and 1 to 2 (the thread becomes an append-only log). |
| Migration keeps the source for recovery (`session-format-v0-to-v1` ... `v3-to-v4`) | `store::read_in`, `store::retire_legacy` | **Ported** in spirit: when a thread saved as one `<id>.json` is carried forward, the original is kept as `<id>.v<N>.bak` and the thread becomes `<id>.jsonl`. |
| `session-persistence`: one writer per session | `runtime::lease`, `store::lease`; taken by a chat run and by a remote-server run | **Ported.** An operating-system file lock on `<id>.lock`, released by the system if the process dies. A second Vivianne that tries to write the same conversation is told to wait instead of overwriting the first one's turn. |
| `session-persistence`: readers never see torn tails or invalid records; a completed flush is the durability barrier | `runtime::log` | **Ported.** Appends are flushed to disk before a save returns; a file that ends in half a line reads as everything before it, and the next save writes it whole; a damaged line elsewhere is an error and the file is set aside as `<id>.jsonl.damaged`, never read as if it were whole. Whole-file rewrites go beside the file and rename over it. |
| `session-checkpoint-policy`: durable before each model request and before top-level tools run; fail-closed | `Agent::set_checkpoint`, `store::checkpoint`; wired in the chat and the remote server | **Ported.** The conversation is saved before every model request and before a step's tools run; if the save fails the run stops with an error before anything is sent or run. A crash loses at most the step in flight. Stopping a run takes what it added back out of the saved copy. |
| `session-persistence-jsonl`: append-only JSONL log, checksummed zstd generations, immutable history, crash-recovery of torn tails | `runtime::log`; `viv thread generations` | **Ported, with two differences.** A save that only adds messages appends them. A save that shortened the history (condensed or rewound) first keeps the old file as `<id>.g<N>.jsonl.gz`, written once and never changed, and starts the next generation; a save that changed earlier messages without shortening (old tool results masked) rewrites in place. Generations are gzip (pure Rust, already in the tree), not zstd, and carry no separate checksum: the compressed stream checks itself and a generation that does not unpack is reported. |
| `session-stats` (turns, steps, LLM / tool / first-token / decode times from the whole log) | `runtime::session_stats::StatsFold`; `viv thread stats` | **Ported.** Turns, steps, tool calls, failures, context messages, model time and tool time, and first-token and decode times: the agent loop times each streamed reply (`Message::timing`) and the figures sum the replies that have it (older replies add nothing, and `timed_steps` says how many were). |
| `session-turn-outline` (every turn with a bounded prompt and response preview) | `runtime::session_stats::OutlineFold`; `viv thread outline` | **Ported.** One line of prompt (50 characters) and up to three of the final answer (120), whitespace collapsed, injected context and condensed checkpoints left out. |
| `session-projection`, `session-projection-cache` (a registry of projections with snapshots, a change feed and a durable checkpoint cache) | `runtime::projection` (`Projection`, `registry`, `project`); cache at `<id>.proj.json` | **Ported, without the change feed.** The registry runs the named folds (stats, outline). The cache keeps each fold's state with how many messages it covers and a SHA-256 of exactly those messages, so a read folds only what was added; a cache whose digest, version or shape does not match is discarded and rebuilt, never trusted. The change feed (subscribers told when a projection changes) is not built: nothing in Vivianne subscribes. |
| `session-title`, `session-title-llm`, `session-title-first-prompt-llm` | `runtime::title` (cleaned first sentence, replaced by a model-written one, a name the person gave is never replaced) | Same job. Not ported: the refresh cadence service and its own request controls. |
| `session-log-deepseek` (incremental canonical session-log upload to the official model API) | `runtime::export`; `viv thread export` | **Ported as a file, not an upload.** The canonical log (a `session` header, then one line per message with its position), with credentials, private keys and the home folder's name taken out unless `--raw`, and `--after N` to continue an earlier export. The upload to one provider's API, its acceptance watermark and its request field are not built: they exist for that provider's service, and sending a conversation anywhere is the person's choice, made by taking the file. |
| `session-telemetry`, `session-telemetry-otel` (ordered copies of session activity to a reporting backend; OpenTelemetry) | `crates/telemetry` (usage) | **Not built, on purpose.** Exporting spans needs an OpenTelemetry SDK and an endpoint, which is a large dependency and a place conversation data could leave the machine by configuration. Local usage counts stay in `crates/telemetry`; the session log file above is what to feed another tool. |
| `working-directory`, `tool-working-directory` (the session's directory can change; survives replay; shown in context) | `tools::workdir` (`WorkingDirectory`, the `working_directory` tool), `Toolbox::execute`, `shell` `cwd`, `run_code`, `Agent::run` | **Ported.** The toolbox holds one shared current directory; relative paths (and the folder `ls`, `grep`, `code_search`, `glob` and `shell` start in) are made absolute from it before a tool runs, so every tool, the shell and `run_code` programs follow it. It can only be moved to an existing directory inside the canonical project folder (symlinks and `..` cannot leave), a move is replayed from the saved conversation's own calls at the start of a run so a resumed conversation is back where it was, and the model is told the current directory in its instructions when it is not the project's. |
| `message-quotes` (quotation controls and Markdown blockquote presentation) | `runtime::quotes` (`quote`, `split`); the chat's "Quote" button under a reply | **Ported.** A quote is plain Markdown (`> ` on every line) with no metadata, as in the original; `split` reads the quotes a message opens with. The chat puts a whole reply into the composer as a quote. Quoting only a selected part of a reply is not built: the Markdown view does not expose its selection. |
| `session` (the core library: events, fork, repair, compaction) | `runtime::session`, `store::fork`, `history::repair`, `compact.rs` | Ported earlier (see `core-package-gaps.md`). |
